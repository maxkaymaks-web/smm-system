# Контент-планировщик

Контент-план — главный статус-менеджер проекта. Он всегда актуален.

## Что приходит в ТЗ

- `context.md` клиента
- `strategy.md` — рубрикатор (обязателен, см. ниже)
- Период: неделя или месяц
- Текущая дата
- Список уже опубликованных тем (из `posts/published/`)

## Что выдаёшь

Три файла в `projects/{ProjectID}/`:

1. `content-plan.html` — брендированный документ для согласования и мониторинга
2. `content-plan.md` — машиночитаемая таблица
3. `content-plan.pdf` — PDF для отправки клиенту

После создания HTML — всегда `node tools/html-to-pdf.js projects/{ProjectID}/content-plan.html`.

## Правило рубрикатора (строгое)

**Нельзя добавлять посты вне рубрикатора.**

- Рубрикатор живёт в `strategy.md` → раздел «Контент-микс»
- Нет рубрики → нет поста
- Если нужна новая рубрика — сначала добавить в `strategy.md`

Рубрикатора нет — запроси создание стратегии. Без него контент-план не создаётся.

## Статусы

| Статус | CSS-класс |
|--------|-----------|
| Черновик | `status-draft` |
| На согласовании | `status-review` |
| Ждём материалы | `status-waiting` |
| Опубликовано | `status-done` |

Триггеры обновления статуса (из сообщения оператора):
- «передали на согласование» → `На согласовании`
- «одобрено» / «опубликовали» → `Опубликовано`
- «передали ТЗ» / «ждём материалы» → `Ждём материалы`
- «вернули на доработку» → `Черновик`

После обновления: `git add . && git commit -m "content-plan: update status post N — {ProjectID}" && git push origin main`.

## Плашки материалов

В колонке «Заметки» — что нужно от клиента:

```html
<div class="needs">
  <span class="need">↗ фото</span>
  <span class="need">↗ видео</span>
  <span class="need">↗ кейс с цифрами</span>
  <span class="need">↗ интервью</span>
</div>
```

Плашки показываются независимо от статуса.

## Структура HTML

Основа — `global/templates/content-plan.html`. Секции:

1. **Header** — лого справа, слева: метка, название клиента, подзаголовок
2. **Stats** — 4 карточки: Постов / Период / Частота / Платформа
3. **Table** — разделители по неделям, 7 колонок: # | Дата | Рубрика | Тема | Формат | Статус | Заметки
4. **Footer** — только дата обновления

## Теги рубрик

| Тип | CSS-класс |
|---|---|
| Образовательный / Экспертный | `tag-tech` |
| Команда / BTS | `tag-team` |
| Кейс / До-После | `tag-case` |
| Продающий / Продукт | `tag-product` |
| Отзывы / UGC / Отрасль | `tag-industry` |
| НИОКР / Уникальная услуга | `tag-rd` |

## Правила планирования

- Чередуй рубрики — не подряд одинаковые
- Стандартный ритм 3 поста в неделю (Пн/Ср/Пт или Вт/Чт/Сб)
- ≥1 продающий пост в неделю
- Темы конкретные: не «о продукте», а «5 причин почему X лучше Y»
- Не повторять темы из `posts/published/`
- Не планировать воскресенье (низкий охват)
- Не планировать праздники без отдельной рубрики

## Формат content-plan.md

```markdown
# Контент-план: {Название}
Период: {дата} — {дата}
Платформа: {платформа} · {ритм}
HTML-версия: `content-plan.html`

| # | Дата | День | Рубрика | Тема | Формат | Статус |
|---|------|------|---------|------|--------|--------|
| 01 | 27.04 | Пн | Команда | … | Текст + фото | черновик |
```

Статусы в md: `черновик` / `согласование` / `ждём материалы` / `опубликовано`.
