# Форма-бриф клиента (survey-intake) — дизайн

> Утверждено оператором 20.06.2026. Лёгкий self-hosted опросник на SurveyJS:
> клиент заполняет по ссылке → ответ падает в S3 → Claude у оператора забирает
> и заводит проект. Без внешних SaaS, без VPN для клиента, без ежемесячной платы.

## Зачем

Сейчас оператор снимает бриф (33 вопроса) вручную — звонком/перепиской. Нужно
дать клиенту самостоятельную ссылку-анкету, чтобы не опрашивать вживую. Клиенты в
РФ → форма на нашем домене (без VPN). Заводим клиента раз в несколько дней →
тяжёлая автоматизация (Make/n8n/платные конструкторы) избыточна; оркестратор —
сам Claude Code, источник истины — Notion + git, как и для всего остального.

Решение по итогам ресёрча: self-host на **SurveyJS Form Library** (MIT, ~50–80 МБ
RAM) — выигрывает у Яндекс.Форм (платно + токен на живом юзере) и у внешних SaaS
(нестабильный доступ из РФ). Сервер seo тянет с запасом (7.8 ГБ, ~3.4 свободно).

## Компоненты

### 1. `tools/survey-service/` — сервис на seo
- Голый `node:http` (паттерн `tools/onboard-service/`), порт `4020`.
- Зависимости: `@aws-sdk/client-s3` (уже в репо).
- Отдаёт статику формы. **SurveyJS вендорим локально** (`public/vendor/`) — без
  CDN, чтобы у клиента в РФ открывалось без VPN и без внешних зависимостей.
- **Публичный** `POST /submit` → валидация + запись JSON в
  `s3://seo/smm/intake/{дата}-{слаг-бренда}-{rand}.json`. Креды — `S3_*` из `.env`.
- **Защищённый токеном read-API** (заголовок `Authorization: <SURVEY_API_KEY>`,
  как `POSTIZ_API_KEY`/`ONBOARD_API_KEY`):
  - `GET /api/intake?since=<ISO>&limit=N` → список заявок (key, дата, бренд).
  - `GET /api/intake/{key}` → одна заявка целиком (читаемые пары вопрос→ответ).
  Claude забирает результаты по API+токену; S3-креды у оператора не нужны.
- Антиспам по-лёгкому (клиенты приглашённые): honeypot-поле, rate-limit по IP,
  лимит размера тела (~256 КБ). Без капчи.
- Конфиг (env): `SURVEY_API_KEY` (токен read-API), `OPERATOR_TG` (дефолт
  `@krMaxim`), `INTAKE_PREFIX` (дефолт `smm/intake/`), `PORT` (дефолт `4020`).

### 2. `public/survey.json` — описание формы
- Вопросы **Q1–Q32** из `agents/brief/questions.md`, переписанные клиентским
  языком (без внутренних пометок-интерпретаций). **Q33 в форму НЕ идёт** (мастер-
  вопрос Максима).
- 8 страниц-секций, прогресс-бар, навигация назад/вперёд, обязательные vs
  опциональные помечены, длинные ответы — `comment`/textarea.
- **Вступительный экран:** что это за анкета + ссылка `t.me/krMaxim` с текстом
  «не хочется заполнять — напишите или надиктуйте голосовым, расшифруем сами».
- Файлы: без загрузки. Где нужен брендбук — поле «ссылка» + приписка «файлы
  пришлёте оператору».

### 3. `tools/intake/check.mjs` — проверялка для Claude/оператора (локально)
- Ходит в read-API сервиса по токену. Env: `SURVEY_API_URL`
  (напр. `https://survey.bitandpix.ru`) + `SURVEY_API_KEY`. **S3-креды не нужны.**
- `node tools/intake/check.mjs` → список заявок (дата, бренд, ключ).
- `node tools/intake/check.mjs --get <key>` → одна заявка в читаемом виде
  (вопрос → ответ), чтобы Claude сразу завёл `new-client.mjs` и заполнил
  context/voice/strategy.

## Поток данных

```
клиент → survey.bitandpix.ru → POST /submit  (публично)
  → s3://seo/smm/intake/{дата}-{бренд}-{rand}.json
  → оператор: node tools/intake/check.mjs → GET /api/intake (Authorization: токен)
  → Claude читает → new-client.mjs + заполняет context/voice/strategy
```

Формат записи в S3:
```json
{
  "submittedAt": "<ISO>",
  "brand": "<Q1>",
  "answers": { "q1": "...", "q2": "...", ... }
}
```

## Деплой

- nginx-vhost `survey.bitandpix.ru` → `127.0.0.1:4020`, TLS через certbot
  (как `tech.bitandpix.ru`). Сервис — systemd-юнит или docker (как onboard-service).
- **Пререквизит оператора:** A-запись `survey.bitandpix.ru → 5.42.117.201`. До неё —
  локальный запуск на `:4020` для теста.

## Обработка ошибок

- Сбой записи в S3 → один ретрай; при повторном сбое `POST /submit` отдаёт 503,
  фронт сохраняет введённое и показывает «попробуйте ещё раз / напишите @krMaxim».
- Невалидное тело / превышен размер → 400.
- Превышен rate-limit по IP → 429.

## Тестирование

- Юнит: `slugify(brand)`, `flattenAnswers(survey.json, data)` (пара вопрос→ответ),
  валидация honeypot/размера.
- Smoke: поднять сервис локально, `curl POST /submit` → проверить запись в S3 под
  `smm/intake/_test/`, затем удалить.

## YAGNI — чего не делаем

Без загрузки файлов, без персональных ссылок под клиента, без капчи, без
авто-записи в Notion (Claude раскладывает заявку сам, human-in-loop).
