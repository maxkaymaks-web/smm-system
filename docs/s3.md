# S3 — гайд для агентов и оператора

> Роль S3 (см. `docs/storage.md`): **(1) всё SMM-медиа** под префиксом `smm/`;
> **(2) архив сессий Claude Code** (`logs/claude-code/…`). Операционка — в Notion, не в S3.
> Переезд на Google Drive рассматривали и **отказались** (14.06.2026, причины — в `docs/storage.md`).

Бинарники (PNG/JPG/PDF/MP4/HTML-рендеры) живут в **S3** Timeweb Cloud, bucket=`seo`, под префиксом `smm/`. В git коммитим только текст (`.md`, `.json`). Локальная файловая система — только для рабочей сессии (`/tmp`, `.s3-cache/`).

## Подключение с новой машины

Параметры подключения (S3-compatible API):

| Поле | Значение |
|---|---|
| Endpoint / Server | `s3.twcstorage.ru` (HTTPS, порт 443) |
| Bucket | `seo` |
| Region | `ru-1` |
| Access Key ID | спросить у Максима / Павла |
| Secret Access Key | спросить у Максима / Павла |
| Path style | **обязательно включить** (Timeweb не поддерживает virtual-hosted style) |

Никакого VPN не нужно — S3 публичный, аутентификация по ключам.

## Способ 1 — CLI через репозиторий (для Claude Code)

```bash
git clone https://github.com/maxkaymaks-web/smm-system.git
cd smm-system
npm install
cp .env.example .env
# вписать S3_ACCESS_KEY и S3_SECRET_KEY (остальное уже заполнено)
```

Дальше — команды `node tools/s3.mjs ...` из секций ниже. Из чата Claude Code можно просто сказать «глянь что лежит в `projects/Lakmoda/posts/drafts/`» — он сам вызовет `list`.

## Способ 2 — Mac GUI (для людей без терминала)

### Cyberduck (бесплатно, для просмотра/скачивания)

1. Скачать с https://cyberduck.io (или `brew install --cask cyberduck`)
2. Открыть → **+ New Connection** (или ⌘N)
3. В выпадашке наверху выбрать **Amazon S3**
4. Параметры:
   - Server: `s3.twcstorage.ru`
   - Port: `443`
   - Access Key ID / Secret Access Key — креды выше
   - Path: оставить пустым
5. **More Options** → **Use path-style requests** ✅
6. Connect → откроется список бакетов → зайти в `seo` → видно всю структуру `projects/...`

Двойной клик — скачать/открыть. Drag&drop — загрузить.

### Mountain Duck ($39, монтирует как сетевой диск Finder)

От того же разработчика что Cyberduck. Подключение то же самое, но S3 примонтируется в Finder как обычный диск — можно открывать файлы напрямую в Preview/Photoshop/итд.

1. https://mountainduck.io (триал 14 дней)
2. New Bookmark → Amazon S3 → те же поля что для Cyberduck
3. Connect → в Finder появится том `seo`

### Альтернативы

- **Transmit 5** (~$45, Panic) — самый шустрый интерфейс, тоже умеет path-style S3
- **S3 Drive** (https://s3drive.app, freemium) — кросс-платформенный
- **rclone + macFUSE** — для тех кто любит CLI:
  ```
  brew install rclone
  rclone config        # new remote → s3 → other → endpoint=https://s3.twcstorage.ru
  rclone mount seo: ~/s3-seo --vfs-cache-mode writes
  ```

## Безопасность ключей

Креды дают **полный доступ** к бакету (read + write + delete). Не выкладывать в публичные репо/чаты/скриншоты. Если ключ утёк — сказать Павлу, ротируем через панель Timeweb.

## Зачем

- **Сервер не перегружается** — 233 MB бинарников ушли с RU-машины
- **Любой агент с любой машины** может прочитать актуальный артефакт без `git pull`
- **Истории — без раздувания .git** (после миграции — `git filter-repo` если надо очистить старое)
- **Шарить с клиентом** — presigned URL прямо из S3

## Где креды

`.env` репозитория:

```
S3_ENDPOINT=https://s3.twcstorage.ru
S3_BUCKET=seo
S3_REGION=ru-1
S3_ACCESS_KEY=…
S3_SECRET_KEY=…
```

Все скрипты `tools/s3.mjs` берут это из `.env`.

## Схема ключей в S3

**Всё SMM-медиа — под префиксом `smm/`** (не в корне бакета). Ключ = `smm/` + относительный путь от корня репо.

```
smm/projects/Bioprintex_Limatex/posts/drafts/29_04_2026-1/slide_01.png
smm/projects/Lakmoda/assets/brand/Цветовая палитра.jpg
smm/projects/BeautyCulture_DariaSopkina/assets/images/before-after/legs_1_after.jpg
```

Дисциплина: «`smm/` + локальный путь = ключ S3». Архив сессий — отдельный префикс
`logs/claude-code/…` (не под `smm/`). В примерах команд ниже префикс `smm/` иногда
опускается для краткости — реальный ключ медиа всегда начинается с `smm/`.

## Команды (tools/s3.mjs)

### Найти / посмотреть что есть

```bash
# по проекту
node tools/s3.mjs list projects/Bioprintex_Limatex/

# по конкретному посту
node tools/s3.mjs list projects/BeautyCulture_DariaSopkina/posts/drafts/22_04_2026-1/

# всё
node tools/s3.mjs list projects/
```

Вывод: `<размер> <дата ISO> <ключ>` + сводка.

### Скачать один файл

```bash
# в /tmp для просмотра
node tools/s3.mjs get \
  projects/Bioprintex_Limatex/posts/drafts/29_04_2026-1/slide_01.png \
  /tmp/preview.png
xdg-open /tmp/preview.png

# не забыть удалить после
rm /tmp/preview.png
```

### Скачать всю папку (для редактирования)

```bash
node tools/s3.mjs sync-down \
  projects/Bioprintex_Limatex/posts/drafts/29_04_2026-1/ \
  /tmp/29_04_2026-1/

# редактируешь / открываешь...

# залить обратно (заменит)
node tools/s3.mjs sync-up \
  /tmp/29_04_2026-1/ \
  smm/projects/Bioprintex_Limatex/posts/drafts/29_04_2026-1/

# почистить
rm -rf /tmp/29_04_2026-1/
```

### Загрузить один файл

```bash
node tools/s3.mjs put /tmp/новый-фон.jpg projects/X/posts/drafts/.../fon.jpg
```

### Поделиться (presigned URL — можно отправить клиенту)

```bash
# ссылка живёт 1 час
node tools/s3.mjs url projects/X/posts/drafts/.../slide_01.png

# или 7 дней (604800 сек)
node tools/s3.mjs url projects/X/posts/drafts/.../slide_01.png 604800
```

URL вида `https://s3.twcstorage.ru/seo/...?X-Amz-Signature=...` — открывается в любом браузере, ничего скачивать клиенту не нужно.

### Удалить (важно — не оставлять мусора)

```bash
# один файл
node tools/s3.mjs rm projects/X/posts/drafts/22_04_2026-1/slide_01_old.png

# целая директория (поддерживает префикс)
node tools/s3.mjs rm projects/X/posts/drafts/22_04_2026-1/ --recursive
```

⚠️ Удаление в S3 **необратимо** (bucket без версионирования). Перед `--recursive` — `list` сначала.

## Workflow для агентов

### Designer создаёт новый слайд

1. Генерация fal.ai → `/tmp/{date}-{N}/bg.jpg`
2. Пишет HTML в `/tmp/{date}-{N}/slide_01.html`
3. `node tools/render-html.js` → `/tmp/{date}-{N}/slide_01.png`
4. `node tools/s3.mjs sync-up /tmp/{date}-{N}/ smm/projects/{ProjectID}/posts/drafts/{date}-{N}/`
5. Вернуть оператору пути/S3-ссылки на превью
6. `rm -rf /tmp/{date}-{N}/` — чисто

### Operator смотрит черновик

Хочет посмотреть полную версию или PDF из S3:

```bash
node tools/s3.mjs list projects/Bioprintex_Limatex/posts/drafts/29_04_2026-1/
node tools/s3.mjs get projects/Bioprintex_Limatex/posts/drafts/29_04_2026-1/slides.pdf /tmp/pdf.pdf
xdg-open /tmp/pdf.pdf
```

### Содержать в чистоте локалку

Раз в неделю:
```bash
du -sh /tmp/*  # что висит
rm -rf /tmp/preview* /tmp/{date}* /tmp/*.pdf
```

Агент сам чистит `/tmp` после задачи. Если упало посередине — может остаться, тогда подмести руками.

## Зачем `--recursive` rm в реальной работе

Сценарий 1: пост ушёл в published, drafts больше не нужны.

```bash
# Переместить в published prefix
node tools/s3.mjs sync-down smm/projects/X/posts/drafts/04_05_2026-1/ /tmp/post-04/
node tools/s3.mjs sync-up   /tmp/post-04/                       smm/projects/X/posts/published/04_05_2026-1/
node tools/s3.mjs rm        smm/projects/X/posts/drafts/04_05_2026-1/ --recursive
rm -rf /tmp/post-04
```

Сценарий 2: эксперимент не удался, всё к чёрту.

```bash
node tools/s3.mjs rm projects/X/posts/drafts/07_05_2026-1/ --recursive
```

## Что НЕ хранится в S3 (живёт в git)

- Тексты: `*.md` (post.md, voice.md, context.md, content-plan.md, …)
- Конфиги: `*.json` (package.json, …)
- Код: `*.js`, `*.mjs`, `*.py`
- Build-time deps:
  - `global/brand/` — лого и шрифты bit&pix
  - `global/templates/` — HTML-шаблоны
  - `projects/*/assets/brand/*.ttf`, `*.otf`, `*.woff2` — шрифты клиента
  - `projects/*/assets/brand/*.png`, `*.svg` — логотипы клиента, используемые в рендере HTML

В `.gitignore` зафиксированы паттерны на бинарники в `projects/*/posts/**` и `projects/*/assets/images/**` — если случайно `git add` — git тихо пропустит.

## Восстановить случайно удалённое

S3 без versioning. Восстановления нет. Если удалил по ошибке:
1. Если файл всё ещё закоммичен в git — `git show HEAD:путь > файл` и заново upload
2. Если потерян — собирать заново (генерация дешевле бэкапов для нашего объёма)

При очень критичных артефактах — делай вручную копию в S3 префикс `archive/`.
