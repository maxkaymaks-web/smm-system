# Глобальные правила SMM-системы

Этот файл читают все агенты при каждой задаче. Приоритет:

1. `projects/{ProjectID}/voice.md` — голос бренда (перекрывает всё)
2. `projects/{ProjectID}/context.md` — контекст клиента
3. `global/rules.md` — этот файл

---

## YAGNI

You Aren't Gonna Need It. Не делать функциональность «на будущее»:

- Не добавлять параметры/опции, которых нет в текущей задаче
- Не плодить fallback-копии «на всякий случай»
- Не оставлять обратной совместимости после миграции — старое удаляется
- Три похожие строчки лучше преждевременной абстракции
- Если оператор передумает — это будет следующая задача, тогда и добавим

Этот принцип бьёт привычку «давай ещё универсальнее» — её нет.

## Хранение файлов

Полная карта (сейчас vs цель) — `docs/storage.md`. Кратко:

- **Операционка** (статусы, план, очередь) — в **Notion** (источник истины), не в `.md`
- **Знания** (`context/voice/strategy/overrides`) и тексты (`.md`/`.json`) — в **git**
- **Бинарники** (HTML-рендеры, PNG/JPG/PDF/MP4) — **сейчас S3** (`s3.twcstorage.ru`, bucket=`seo`);
  цель — Google Drive (Фаза 3, `tools/gdrive.mjs` ещё не внедрён, пиши в S3 как раньше)
- Локально работа через `/tmp/{ProjectID}-{date}-{N}/` — рабочая директория задачи
- После задачи (upload → доставка) — **`/tmp` чистится агентом**; если упало — оператор руками

Запрещено:
- Коммитить `.html`, `.png`, `.jpg`, `.pdf`, `.mp4` в `projects/*/posts/**` или `projects/*/assets/images/**` (`.gitignore` блокирует)
- Оставлять файлы в репо «на потом» — либо в хранилище, либо удалить
- Держать большие файлы в `/tmp` дольше нужного сеанса работы

Гайд по S3 — `docs/s3.md`.

`projects/{ProjectID}/voice.md` и положить его содержимое **текстом в ТЗ** агенту.

## LLM-вызовы

Основная работа = Claude через подписку Claude Code (без gateway). Прямые ключи
в коде не использовать — только из `.env`.

Генерация изображений/видео/аудио — `fal.ai` напрямую через клиент
`@fal-ai/client`, без прокси. Не выставляй `HTTPS_PROXY` и не паникуй, если её
нет в `.env`.

### Text-to-image: ровно две разрешённые модели

| Когда | Модель |
|---|---|
| Дефолт (фон, продукт, портрет, lifestyle, текстура) | `fal-ai/nano-banana-2` |
| На картинке нужен разборчивый длинный/мульти-язычный/типографский текст | `openai/gpt-image-2` |

Никакие другие text-to-image модели (Flux любой версии, Ideogram, Recraft, Seedream, Imagen, Qwen, SDXL, Nano Banana Pro, и т.д.) в проекте не используются — ни через CLI `tools/generate-image.mjs`, ни прямыми вызовами `fal.run(...)` из агентов/скриптов. Img2img / inpainting — через `openai/gpt-image-2/edit` (тот же режим, что и t2i, плюс `image_url`/`mask_url`) или повторной генерацией в nano-banana-2 с `image_urls` массивом референсов.

Не t2i (используется как было): `fal-ai/bria/background/remove` (фон), `fal-ai/seedvr/upscale/image` / `fal-ai/esrgan` (апскейл), `fal-ai/any-llm/vision` (анализ референсов), видео-модели Kling/Veo/Sora, аудио ElevenLabs/Kokoro.

## Форматирование постов (ВКонтакте — основной канал)

- Длина: 300–900 символов для охватного, 900–2200 для экспертного
- Абзацы: 2–4 строки, воздух между ними
- Эмодзи: 1–3 на пост, по смыслу
- CTA — обязательно, в последнем абзаце, конкретный
- ВК-хэштеги: 3–5 тематических (если включены для проекта)
- Точка перед эмодзи не ставится: ✅ `текст 🔬` ❌ `текст. 🔬`

## Дизайн постов

- Холст: 1080×1080 (квадрат) или 1080×1350 (портрет)
- Отступы от краёв: ≥60px
- Текст на изображении: ≤20% площади
- Шрифты: системные или Google Fonts (`@import` в HTML)
- Чисто белый фон не используем — `#f5f5f5` или цвета бренда
- Контраст текст/фон ≥ 4.5:1
- `overflow: hidden` на корневом контейнере
- Без `<img src="http...">` — только локальные пути или CSS `background-image`

## Работа с файлами и изображениями

Эти правила бьют типичные провалы агентов на длинных задачах — галлюцинации имён файлов, чтение бинарей как текста, тишина при работе.

**1. Сначала `ls`, потом `read` / `image`.** Перед чтением любого файла на диске — сначала `ls -la <директория>` (или `node tools/s3.mjs list <префикс>` для S3). Имена из своего же контекста, которые «вроде помнишь», доверять нельзя — особенно если прошёл рестарт сессии или несколько шагов назад. Если файл не нашёлся — сначала `ls` родительской папки, потом думай.

**2. Изображения (`.jpg`, `.jpeg`, `.png`, `.webp`) — только через image-tool (vision).** `read` на jpg/png бесполезен (бинарь), это пустая трата model_call. В Claude Code картинки читает встроенный vision; для batch-анализа референсов — `tools/analyze-image.mjs` (fal.ai vision).

**3. Список файлов в подзадачу — целиком, не пересказом.** Если запускаешь подагента или новую итерацию работы с пакетом фоток/файлов — передавай список как есть (вывод `ls`), а не «там 24 файла с похожими именами». Подагент тоже галлюцинирует имена, если их нет в явном виде.

## Честность про результаты инструментов

Запрещено отчитываться оператору об успехе того, чего не сделал. Это самое жёсткое правило.

- Если tool (`image_generate`, `fetch`, `read`, `bash`, и т.п.) вернул ошибку — пиши **прямо**: «упал tool X с ошибкой Y, картинку не сделал». Никаких «✨ готово!», описаний несуществующего результата, выдумок про «использовал FLUX Pro 1.1 Ultra», `reverse-prompt методологию` и подобный bullshit.
- Если на половине пути что-то сломалось — отчитайся, что успел, а что нет. Не маскируй обрыв успехом.
- Если оператор просил конкретный артефакт (картинка / PDF / пост) и ты его НЕ получил — ОБЯЗАН сказать «не получилось», даже если очень хочется выкрутиться текстом.
- Файлы, ссылки, артефакты в ответе оператору — только реально существующие (`ls`-ом проверил). Не описывай артефакт, которого нет.

Простое правило: если tool упал — оператор узнает первым, фиксом займётся он или разработчик. Когда модель сочиняет успех — это разваливает доверие ко всей системе.

## Защита от лупов на tool-failures

Эти лупы выжирают токены и деньги пачками. Конкретные правила:

**1. `Edit failed: identical content` — НЕ повторять.** Если редактирование файла упало с «replacement produced identical content», это значит, что искомый текст уже совпадает с новым. **Не перечитывай файл, не пытайся снова.** Считай задачу выполненной (нужное состояние уже в файле) и переходи к следующему шагу. Если действительно нужно изменить что-то другое — сначала `read` файл и найди реальный текст, который надо заменить.

**2. Та же ошибка `image_generate: fetch failed` дважды подряд — стоп.** После двух одинаковых fetch-фейлов прокси/сети не пытайся в третий раз — это лишние 30K input tokens на каждый ретрай. Скажи оператору «fal.ai сейчас не отвечает» и остановись. Оператор разберётся.

**3. `read failed: ENOENT` — `ls` родителя, не угадывай.** Если файл не нашёлся — НЕ пытайся «вариант имени №2» по памяти. Сделай `ls -la` родительской директории и работай с реальным списком. Иначе галлюцинация имён + read fail = бесконечный цикл.

**4. Три одинаковых tool-call подряд с тем же результатом — abort.** Если за один запрос ты три раза подряд вызвал один tool с одинаковыми параметрами и получил один результат — задача застряла. Остановись и попроси оператора помочь.

Каждый бесцельный ретрай — это 30–100К токенов в системном промпте. Дешевле остановиться и спросить.

## Стоп-слова и табу

- Без «уникальный», «лучший», «качественный» (без доказательств)
- Без «просто», «буквально», «на самом деле», «конечно»
- Без капслока на целое предложение
- Без списков длиннее 7 пунктов
- Без копирования текстов конкурентов
- Без поста без CTA

## Файловая структура постов

```
projects/{ProjectID}/posts/drafts/{dd_mm_yyyy}-{N}/
```

- `dd_mm_yyyy` — дата публикации из контент-плана
- `N` — порядковый номер поста в этот день, с 1
- Несколько в день: `22_04_2026-1`, `22_04_2026-2`

Состав:
- `post.md` — текст поста
- `slide_NN.html` + `slide_NN.png` — карусели
- `post.html` + `post.png` — одиночный

## Git-синхронизация

Коммит и пуш разрешены, но **каждый раз спрашивай подтверждение оператора** перед
`git commit` и `git push` — не делай автоматически (правило из `CLAUDE.md`).

Когда уместно предложить коммит:
- Создал/изменил файл проекта (`.html` / `.md` / `.json` / `.py` / `.js`)
- Завершил задачу или законченный шаг

Формат коммита:

```
<scope>: <action> — <ProjectID>
```

Примеры:
- `posts: статус #03 → на согласовании — BeautyCulture_DariaSopkina`
- `analytics: competitors analysis — Bioprintex_Limatex`
- `designer: render slides 01-05 — Lakmoda`

Скоупы: `posts`, `content-plan`, `analytics`, `brief`, `designer`, `agents`, `tools`, `docs`, `memory`.

Не делать: `--no-verify`, `--amend` без явного запроса оператора, force push в main.
