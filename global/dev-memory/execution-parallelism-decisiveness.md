При прогоне implementation-плана (subagent-driven и т.п.) оператор хочет, чтобы
независимые подсистемы шли **параллельно** (например backend || frontend),
даже в одной ветке main, а не строго последовательно. И не любит, когда по
**процессным** мелочам его дёргают multiple-choice вопросом (AskUserQuestion) —
надо решать самому и просто делать.

**Почему:** сказал «так ебаш параллельно бэк и фронт в этой ветке да и всё» и
отклонил multiple-choice вопрос про способ параллелизации.

**Как применять:** при исполнении планов запускать независимые потоки конкурентно
(в одном дереве на main — агенты пишут в непересекающиеся папки и НЕ трогают git,
коммиты делает контроллер по путям, чтобы не было гонки за .git/index).
AskUserQuestion беречь для реальных продуктовых/дизайн-развилок, а не для механики
исполнения. Связано: [[smm-app-client-cabinet]].
